# API Key 管理面板设计

状态：已实现。本文整理控制台面板、网关鉴权和验收标准。

## 目标与默认值

管理员可在控制台创建、复制、编辑、启停和吊销 API Key，为不同调用方设置并发数、有效期、用量额度和可用模型。配置文件中的 `api_key` 称为全局 Key；面板创建的称为托管 Key。

| 创建项 | 默认值 | 规则 |
| --- | --- | --- |
| Key 值 | 随机生成 | 也可自定义；创建后 Key 值不可编辑，轮换时创建新 Key 再吊销旧 Key |
| 启用状态 | 启用 | 支持停用和重新启用 |
| 并发上限 | 1 | 同一 Key 同时在途的推理请求数，须为正整数；同一客户端的多个请求也分别计数 |
| 有效期 | 永久，即时生效 | 面板中永久即没有开始和结束时间（切换为永久会一并清除）；期限模式须指定开始和结束时间，精确到秒。接口层仍允许永久 Key 单独设置 `starts_at` |
| 额度类型 | 不限 | 可改为 Credits 或 Cost；每个 Key 只按其中一种判断是否超额 |
| 可用模型 | 不限制 | 以后新增的模型也可用；切换到白名单后只允许已配置的模型 |

本期支持手动重置用量，不做周期重置、额度预扣或按客户端身份独占，也不新增每个 Key 独立的模型别名。

## 鉴权与请求处理

| 凭证 | 权限 |
| --- | --- |
| 全局 Key | 必须在 `config.json` 中配置。可访问管理和推理接口，绕过托管 Key 的有效期、额度、模型白名单和单 Key 并发限制；网关原有的全局并发保护仍生效 |
| 控制台 Session | 可访问管理接口，沿用现有 Cookie 和 `X-Dashboard-Request: 1` 校验；不能作为推理凭证 |
| 托管 Key | 仅允许 `POST /v1/chat/completions`、`POST /v1/responses`、`POST /v1/messages`、`GET /v1/models` |

API Key 继续接受 `Authorization: Bearer <key>` 和 `x-api-key: <key>`；同时存在时沿用 Bearer 优先。托管 Key 按方法与路径精确匹配，不能访问 `/v1/models/list`、`/v1/models/alias/*`、账号导出或 `/v1/api-keys/*`。`HEAD /v1/models` 虽会被路由层当作 `GET` 处理，但方法不是精确的 `GET`，托管 Key 同样拒绝（全局 Key 行为不变）。公开探针、登录和会话生命周期接口沿用原有规则。

### 准入顺序与并发槽

1. 鉴权中间件识别凭证；托管 Key 依次检查启用、未生效、过期、额度，按顺序返回第一个错误。通过后将已验证的托管 Key ID 注入请求上下文。
2. 推理 handler 解析请求，应用全局别名，查找模型目录中的目标 ID 并检查白名单。通过后立即尝试占用该 Key 的并发槽；达到上限就拒绝，不排队。占槽前按当前已提交的策略和用量复核，避免等待模型解析期间错过配置或用量变化。
3. 一个入站请求只占一个槽。Responses 的自动或显式压缩以及后续正式推理共用该槽，账号重试也不重新占槽。压缩上下文窗口的查找、摘要和正式推理都使用入口已授权的模型目标，避免在两次调用之间重新解析已变化的别名；客户端响应仍保留原始模型名。
4. 槽持有到响应体结束或被丢弃；完成、失败、断开，以及 handler 在创建响应体前退出都须释放。沿用上游空闲读超时，无需额外的响应总时长上限。更改并发上限时保留在途计数，后续请求按新上限准入。

并发计数用“每个托管 Key 一个原子计数器，准入时与当前上限比较”实现，不用 `tokio::sync::Semaphore`（它不能缩小容量）。槽的守卫持有该计数器的 `Arc`，Drop 时减一，因此 Key 被吊销或改上限之后，在途请求仍能正确释放。

`GET /v1/models` 同样校验 Key 状态和额度，再过滤列表；不占推理并发槽，也不增加用量。过期、停用、吊销和改配置只影响后续准入，不切断已获准的流。

鉴权中间件在请求日志中间件之外，因此启用、生效、过期、额度检查失败的请求不写请求日志；模型白名单和并发上限在 handler 内判断，此时请求体已被日志中间件缓冲，被拒绝的请求（包括客户端按 `Retry-After` 重试的 `429`）仍会写入一行请求日志，按现有保留期清理。这是已知开销，不为此调整中间件顺序。

### 客户端错误契约

推理和模型查询的入口错误沿用 `GatewayError` 的 `{ "error": { "message", "type", "code" } }` 信封，在开启 SSE 前返回真实 HTTP 状态。现有上游错误和流内错误处理保持原有语义；网关全局并发保护触发时仍返回 `503`，可与单 Key 的 `429` 区分。

| 条件 | HTTP | `error.type` | `error.code` | 说明 |
| --- | --- | --- | --- | --- |
| 缺少、无效、已吊销或凭证不适用于当前路由 | 401 | `authentication_error` | `invalid_api_key` | 不在错误中回显 Key |
| 已停用 | 401 | `authentication_error` | `api_key_disabled` | 重新启用后可用 |
| 未到开始时间 | 401 | `authentication_error` | `api_key_not_yet_valid` | 开始时间到达后可用 |
| 到达或超过结束时间 | 401 | `authentication_error` | `api_key_expired` | 已获准的流可继续 |
| 已用额度达到或超过总额度 | 403 | `permission_error` | `insufficient_quota` | 不发送 `Retry-After` |
| 模型不存在或不在白名单 | 404 | `invalid_request_error` | `model_not_found` | 两者使用同一错误 |
| 达到单 Key 并发上限 | 429 | `rate_limit_error` | `api_key_concurrency_limit` | 响应头 `Retry-After: 1` |
| 额度受限的托管 Key 无法建立结算记录 | 503 | `server_error` | `usage_tracking_unavailable` | 响应头 `x-should-retry: false`；不限额的托管 Key 和全局 Key 不受影响，仅记录错误日志 |

管理接口不使用上表的 `invalid_api_key`：Session 失效或过期时保留原有的 401 提示“登录已失效/已过期，请重新登录”；仅当调用方带着托管 Key 访问管理接口时，才返回 `invalid_api_key`。

## 有效期与状态

接口和 SQLite 使用 Unix 时间戳（UTC 整数秒）。面板的创建时间、有效期和日期选择器统一使用固定 UTC+8，与浏览器、服务器的本地时区无关。无开始时间则立即生效；`ends_at = null` 表示永久；有期限时须满足 `starts_at < ends_at`。到达开始秒即可使用，到达结束秒立即失效。`/v1/api-keys/*` 接口的全部时间字段（含 `created_at`）都是 UTC 秒整数，与统计接口输出 UTC+8 字符串的格式不同；面板使用自己的格式化函数，不复用统计页和日志页的。

状态不落库。列表以同一个当前时间计算状态和筛选结果，按下表从上到下命中第一项：

| 优先级 | 状态 | `status` | 条件 |
| --- | --- | --- | --- |
| 1 | 已禁用 | `disabled` | 已停用 |
| 2 | 未生效 | `not_yet_valid` | 当前时间早于开始时间 |
| 3 | 已过期 | `expired` | 当前时间大于等于结束时间 |
| 4 | 已超额 | `quota_exceeded` | 已用达到或超过当前额度 |
| 5 | 有效 | `active` | 其余情况 |

“永久 / 期限”是单独的有效期类型筛选；永久 Key 也可处于未生效、已超额或已禁用状态。并发占满是临时拒绝条件，不改变列表状态。

## 模型白名单与全局别名

白名单保存上游模型目录的公开 `id`，即 `GET /v1/models` 的 `data[].id`。该 ID 可能与实际发给上游的内部 `model` 字符串不同。入口通过 `ModelAliasStore` 做一次精确别名解析，对解析后的目录 ID 校验存在性和白名单。面板也从同一个 store 读取别名，不为 Key 保存映射副本；别名变更影响下一次解析。

例如，两个 Key 都选了 `anthropic-claude-sonnet-5`：

| 全局映射状态 | 客户端请求 | 结果 |
| --- | --- | --- |
| 有 `claude-sonnet-5 → anthropic-claude-sonnet-5` | `claude-sonnet-5` | 两个 Key 均可调用目标模型 |
| 删除该映射，且目录没有 `claude-sonnet-5` | `claude-sonnet-5` | 两个 Key 均返回模型 404 |
| 不论该映射是否存在 | `anthropic-claude-sonnet-5` | 目录中存在该 ID 时可直接调用 |
| 目标不在白名单，或目标已不在目录 | 对应别名或原始 ID | 返回相同的模型 404 |

* `model_ids = null` 表示不限制：`GET /v1/models` 返回当前目录，以后加入目录的模型自动可用。
* 非空 `model_ids` 表示白名单：`GET /v1/models` 只返回目录与白名单的交集，保留现有模型列表格式，不额外添加别名条目。
* “全选”只选中弹窗加载时的可用模型，保存后形成快照；新增上游模型须手动加入。面板提示这个差异，并提供“恢复不限制”。空白名单拒绝保存。
* 已保存、后来下线的 ID 在预览和配置弹窗中标记“已下线”，仍计入已配置数量，可保留或取消，不能新加目录中不存在的 ID。模型目录复用现有缓存；下线判断基于网关当前取得的目录。

## 用量结算与存储

`api_keys` 使用现有 `accounts_db` 的 SQLite 连接，按稳定 `id` 存储 Key 值、启停、并发数、有效期、额度类型及上限、累计 Credits 和 Cost、白名单、创建及更新时间。`id` 为 `TEXT` 类型的 ULID（沿用 `util::new_ulid`；`id` 不是凭证，不要求不可猜测），不使用 SQLite 整数 `rowid`：未加 `AUTOINCREMENT` 的整数主键会在删除最新一行后复用同一个值，使“重建获得新 ID”的保证失效。Key 值唯一且不得与全局 Key 重复；启动时也检查冲突，避免更换全局 Key 时意外给托管 Key 提权，冲突时在控制台（stderr）输出原因和冲突托管 Key 的 `id`（不输出 Key 值）并退出，不提供自动修复。

* 随机 Key 由服务端用系统安全随机源生成，可用 `sk-` 加 32 字节随机值的十六进制编码。读取随机源失败则创建失败，不使用 UUID/ULID 的时间回退。自定义 Key 长度须在 16 到 128 个字符之间，由不含空白的可见 ASCII 字符组成；重复返回冲突。长度下限针对的是误填弱值：服务监听 `0.0.0.0` 且鉴权没有限速或锁定，过短的 Key 可被远程在线猜测。
* 吊销删除可用凭证和策略，保留历史统计。重建相同的自定义字符串时获得新 ID、用量从零开始，旧请求的结算不能落到新 Key；重用原字符串也会让旧持有者看到的凭证重新有效，正式轮换应生成新值。吊销时仍在途的请求在结束时照常写入统计终态：对已删除 Key 的用量更新影响 0 行，不视为错误，也不回滚统计写入。
* 只结算 `status = completed` 且 `call_type = inference` 的托管 Key 上游尝试。读取上游 SSE 的 `usage.total_credits` 和 `usage.total_cost`，不限额时也累计两项；摘要、失败、取消和中断的尝试以及全局 Key 均不计。统计页保留原有记录和汇总口径。
* 从已鉴权的请求上下文传递托管 Key ID 至 `CallContext`，Responses 延迟执行的 SSE 也须保留它。复用 `Attempt` 结算入口：统计终态写入与用量更新放在同一 SQLite 事务，仅本次更新了尚未结算的统计行时才累加。提交成功后标记完成并更新缓存；重试使用原结算快照，流丢弃不得把待重试的完成事件覆盖成取消。托管 Key 的正式推理须先建立结算记录。现有 `Attempt::start` 在统计行插入失败时只记日志并让请求继续，这会让额度记不上：额度类型为 Credits 或 Cost 的托管 Key 在此处拒绝请求（错误见上表 `usage_tracking_unavailable`），不限额的托管 Key 和全局 Key 保持放行，并记录带 Key ID 的错误日志。
* Credits 和 Cost 分别用 `i64` 定点整数保存，单位为 1e-9（九位小数，可表示约 9.2e9）。真实抓包的 Cost 已有七位小数（如 `0.0091105`），六位精度会在每次结算时丢失一部分。管理接口用十进制字符串传递额度，接受至多九位小数，限额须大于零且在可存范围内；上游值按同一精度量化，累加使用饱和加法。面板展示精度与统计页一致（Cost 六位、Credits 四位）。字段缺失、非法或溢出时记录带尝试 ID 的异常，保留原始统计，有效字段仍结算。上线时用真实成功调用样本复核两项字段及精度。
* 准入条件为 `used < limit`。这是事后结算的软上限：已准入的请求仍可继续并让累计值超过限额；后续请求会被拒绝。压缩摘要及提前断流且未到成功终态的开销不扣额度，托管额度与上游最终账单可能不同。
* 修改额度类型、总额度或有效期不会清空用量。重置用量时将两种累计值同时归零；重置后才结算的在途请求仍计入，历史统计保留。鉴权只读内存状态，不扫描 `statistics.usage_json`。所有改变用量或策略的 SQLite 提交（管理写入、结算、重置）都在持有 `Db` 连接互斥锁期间提交并发布内存缓存，缓存锁只在此时短暂持有且不再获取其他锁，因此发布顺序等于提交顺序：结算与重置交错时，缓存不会与数据库不一致。

限额 Key 的流式 Responses 在 SSE 开启前为第一次正式推理预留结算记录，选定账号后绑定，未使用的记录会删除，且不在统计页展示。SSE 开启后若重试无法建立结算记录，停止该次上游调用，并通过流内错误报告。

为支持随时复制，托管 Key 在 SQLite 存明文，管理列表返回完整值。面板默认脱敏展示，复制使用完整值；管理响应使用 `Cache-Control: no-store`，前端不把完整值放进 URL、浏览器持久存储或诊断日志，退出或会话失效时清理面板数据。控制台会话、数据库及备份都应按可读取凭证管理。全局 Key 不出现在 API Key 面板列表中。

统计接口 `/v1/statistics/list` 和 `/v1/statistics/detail` 沿用现状，仍返回每一行的明文 `api_key`，其中包含全局 Key 和已吊销的 Key。这一点已确认保留：控制台只有管理员能登录，统计库与请求日志同样按可读取凭证管理。因此面板的默认脱敏只防旁观，不构成访问控制，不能把它当作“看不到完整 Key”的保证。

## 管理接口与面板

### 管理接口

接口统一为 `POST /v1/api-keys/<操作>`，复用现有 `{code, message, data}` 管理响应。通过不可变的 `id` 指定操作对象，Key 字符串用于创建、列表筛选和复制。

| 操作 | 请求字段 | 结果 |
| --- | --- | --- |
| `list` | `page`、`page_size`、`api_key`、`status`、`validity` 均可选；Key 精确匹配，筛选取交集，`validity` 为 `permanent` 或 `period` | 返回 `Page`，按创建时间、ID 倒序；列表项包含完整及脱敏 Key、状态、并发上限、有效期、额度、两种累计值、已配置模型数量和创建时间 |
| `create` | `mode` 为 `random` 或 `custom`；自定义传 `api_key`；可传 `concurrency_limit`、`starts_at`、`ends_at`、`quota_kind`、`quota_limit` | 返回新建条目；默认启用，模型不限制 |
| `update` | `id`，以及需变更的 `enabled`、`concurrency_limit`、`starts_at`、`ends_at`、`quota_kind`、`quota_limit` | 返回更新后的条目；省略字段表示不变，时间传 `null` 表示清除对应边界 |
| `model-options` | `id` | 返回全量模型、当前全局别名、选中状态，以及已选但下线的 ID，用于预览和配置；不分页 |
| `update-models` | `id`、`model_ids` | 保存去重后的非空白名单，或传 `null` 恢复不限制；返回更新后的条目 |
| `reset-usage` | `id` | 清零两种累计值并返回更新后的条目 |
| `delete` | `id` | 吊销并返回操作结果 |

状态不落库，因此 `list` 先读取内存中的全部托管 Key，用同一个当前时间计算状态并应用筛选，再分页；托管 Key 数量很小，不需要为此建索引。分页沿用现有默认值（第 1 页、每页 10 条，每页上限 100）。`quota_kind` 为 `unlimited`、`credits` 或 `cost`；切到不限时将 `quota_limit` 置为 `null`，两种限额模式必须有总额度。条目返回 `used_credits`、`used_cost` 两个十进制字符串，以及 `model_count`（不限制时为 `null`，白名单时为已配置数量）。参数无效返回 `400`，目标 ID 不存在返回 `404`，Key 与已有 Key 或全局 Key 冲突返回 `409`。所有写操作都在服务端校验参数。

### 面板交互

* 控制台增加“API Key”导航项。顶部提供 Key、状态和有效期类型筛选以及“新增”按钮；复用现有分页和表格组件。
* 表格显示 API Key 与复制图标、状态、有效期、创建时间、并发上限、已用 / 总额度、模型和操作。白名单显示已配置数量（含下线）；不限制显示“全部模型”，点击后可在预览中查看当前目录及数量。预览为只读弹窗，不分页。
* 新增表单支持随机、自定义；编辑可变更有效期、并发、额度和启停。模型配置弹窗支持全选、单选及“恢复不限制”，并说明“全选”只保存当前快照。重置用量和吊销需要确认。
* 优先使用 `navigator.clipboard.writeText`；不可用或失败时尝试 `document.execCommand('copy')`。只有确认写入才提示成功，两种方式都失败时提供可选中的完整 Key 供手动复制。
* 复用控制台的会话恢复和请求逻辑。切换面板、关闭弹窗或退出时丢弃相应的过期响应，避免异步请求把已清除的敏感数据写回页面。新面板使用独立的 UTC+8 格式化和输入转换，不修改日志页或统计页。

## 实施顺序与升级

1. **存储与鉴权**：新增 `src/apikey/` 和 `api_keys` 表，接入 [AppState](../src/server/state.rs) 和 [存储 schema](../src/storage/schema.rs)。在 [鉴权中间件](../src/server/middleware/auth.rs) 区分凭证和方法白名单；在 [推理入口](../src/server/handlers/inference/mod.rs) 接入模型校验、并发和列表过滤，在 [统计结算](../src/statistics/mod.rs) 接入托管用量。SQLite 持久化策略和用量，缓存和并发计数在网关进程内；本期按单实例部署设计。
2. **管理接口**：在 [管理路由](../src/server/handlers/management/mod.rs) 注册 `/api-keys/*`，接入管理鉴权和响应包络。由后端处理参数校验、同名冲突、额度重置和启停。
3. **前端面板**：新增 `src/page/views/api-keys.js`，由 [控制台入口](../src/page/views.js) 导入和挂载，复用 `ui-table`、日期选择器和提示组件。

第 1 步还牵涉下列现有代码的改动，实现前需按此估算工作量：

* [error.rs](../src/error.rs)：`ErrorDetail.code` 目前固定为 `None`，须让 `GatewayError` 能携带 `code`，并新增 403 变体和 503 的 `usage_tracking_unavailable`；`Retry-After` 目前只由 `RateLimited` 设置，且会把“(retry-after: Ns)”拼进 `message`，单 Key 并发上限复用它时接受这一文案。
* [pipeline.rs](../src/server/pipeline.rs) 的 `events` 内部调用 `resolve_model`，[compact.rs](../src/server/compact.rs) 的 `plan` 又单独解析一次别名。要让压缩和推理使用入口已授权的目标，两处签名都要改为接收已解析的目标，[responses.rs](../src/server/handlers/inference/responses.rs) 的流式与非流式路径同步调整。
* [statistics/store.rs](../src/statistics/store.rs) 的 `finish` 丢弃了受影响行数，须改为返回该值，“仅本次更新了尚未结算的统计行时才累加”依赖它。
* 托管 Key ID 由鉴权中间件写入请求扩展，[request_logging.rs](../src/server/middleware/request_logging.rs) 构造 `RequestContext` 时读取，两处都要改。

这是一次配置兼容性变更：旧部署若未设置 `api_key`，升级前须参照 [配置模板](../config.example.json) 填写非空的全局 Key，并为原本匿名调用的客户端配置 API Key，否则新版本无法启动或原调用收到 `401`。实现时同步更新 `Settings`、启动提示、账号导出中不再适用的“未配置”分支、测试配置、README 和配置模板。升级自动建表，已有统计不回填托管额度。

## 验收用例

| 场景 | 应有结果 |
| --- | --- |
| 全局 Key 缺失、为空或与已有托管 Key 冲突 | 启动失败，控制台输出原因；冲突时附带托管 Key 的 `id`，任何情况下都不输出 Key 值；全局 Key 合法时不受托管限制 |
| 管理 Session、托管 Key 和两种请求头 | Session 可管理但不可推理；托管 Key 仅通过四个精确的方法和路径；管理子路径与非允许方法（含 `HEAD /v1/models`）均拒绝，全局 Key 的 `HEAD` 行为不变；两种头沿用原优先级 |
| 随机/自定义创建、冲突与吊销重建 | 随机源失败时不生成凭证，非法字符、少于 16 或多于 128 个字符、重复值被拒绝；重建同一字符串得到新 ID 和零用量，删除最新创建的 Key 后再创建也得到不同的 ID；旧流不污染新额度 |
| 时间边界、状态和筛选 | 起始秒通过，结束秒拒绝；按优先级计算状态；跨浏览器时区显示相同的 UTC+8；有效期类型及状态可独立筛选 |
| 上限 1，同一 Key 并行调用 | 合法的第二个推理请求返回 `429` 和 `Retry-After: 1`；不同 Key 独立；模型或额度不符合时优先返回对应错误 |
| SSE 完成、上游失败、响应体未消费或客户端断开 | 并发槽释放；Responses 摘要和推理之间持续持有同一个槽，失败或仅执行摘要也只占一个槽 |
| 额度恰好耗尽、修改维度、重置 | `used == limit` 时返回 `403`；不限仍累计，切换维度保留用量；重置同时清零并保留历史，后续完成的在途请求正常结算；结算与重置并发交错后，内存缓存与数据库一致 |
| 正式调用、账号重试、压缩和重复终态 | 仅成功的正式推理增加两种用量；失败重试、摘要、取消和中断不计；重复结算或事务回滚重试不重复扣费；七位小数的 Cost 不被截断 |
| 吊销与统计写入失败 | 吊销期间完成的在途流，统计行正常落库，既不累加也不报错；统计行插入失败时，Credits/Cost 限额的托管 Key 返回 `503`（带 `x-should-retry: false`），不限额的托管 Key 和全局 Key 继续放行 |
| 两个 Key 共用别名、全选与恢复不限制 | 新请求使用当前映射；仅目标 ID 参与授权；模型列表按白名单过滤，新增模型不会自动进入快照；可移除下线条目 |
| 创建、编辑、预览、复制和退出 | 模型弹窗全量且不分页；HTTPS/本地及局域网 HTTP 可复制或提示手动复制；退出后清理数据，旧请求不能写回 |
